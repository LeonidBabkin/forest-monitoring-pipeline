# Модуль 1: Топографическая коррекция SCS+C (Sentinel-2 L2A)

## 📌 Суть модуля (Простыми словами)
Представьте, что вы фотографируете один и тот же лес в солнечный день. На склоне, который смотрит на солнце, лес будет казаться ярко-зеленым. А на склоне, который находится в тени — почти черным. 
Если алгоритмы (например, LandTrendr в Модуле 3) увидят эти две фотографии, они решат, что на втором склоне лес погиб.

**Модуль 1 — это «фоторедактор».** Он берет спутниковый снимок, находит все теневые и солнечные склоны, и **выравнивает их яркость** до среднего уровня, используя физическую модель рефлексии света (метод **SCS+C**). В результате здоровый лес на всех склонах выглядит одинаково.

## 🏗 Архитектура: Два пути к одной цели
Главная особенность Модуля 1 в том, что он поддерживает **две разные логики получения данных**. Математическое ядро (расчет коррекции) у них общее, но способ попадания снимков в программу — разный.

```text
                  ┌──────────────────────────────┐
                  │  ЕДИНОЕ МАТЕМАТИЧЕСКОЕ ЯДРО  │
                  │     (m1_scsc_local.py)       │
                  │  Расчет C, cos(i), SCS+C, QC │
                  └──────────────▲───────────────┘
                                 │
                 ┌───────────────┴───────────────┐
                 │                               │
      ┌──────────┴──────────┐         ┌──────────┴──────────┐
      │  ПУТЬ 1 (Локальный) │         │  ПУТЬ 2 (Облачный)  │
      │  run_m1_local.py    │         │  fetch_data_stac.py │
      └──────────▲──────────┘         └──────────▲──────────┘
                 │                               │
      Вы вручную скачали сцену         Автоматический поиск 
      и положили в data/raw/           в каталоге Planetary Computer
```

### 🛠 Путь 1: Локальная обработка (`run_m1_local.py`)
*   **Для чего нужен:** Для отладки, проверки гипотез или работы без интернета.
*   **Как работает:** Вы вручную скачиваете снимки Sentinel-2 (B04, B08, B12, SCL) и файл `MTD_TL.xml` (с углами солнца), кладете их в папку `data/raw/`. Скрипт читает их с диска, обрезает по AOI и запускает математику.
*   **Плюсы:** Полный контроль над тем, какие именно снимки обрабатываются.
*   **Минусы:** Не подходит для обработки временных рядов (за 9 лет вручную можно сойти с ума).

### ☁️ Путь 2: Облачная обработка (`fetch_data_stac.py`)
*   **Для чего нужен:** Для автоматического сбора данных за годы (масштабируемый пайплайн).
*   **Как работает:** Скрипт сам подключается к каталогу Microsoft Planetary Computer (через протокол STAC), ищет нужные сцены по датам и облачности, скачивает **только маленький кусочек** (ваш AOI) из облака, подготавливает его и запускает то же самое математическое ядро.
*   **Плюсы:** Скорость, автоматизация, экономия дискового пространства (не нужно качать гигабайты).
*   **Минусы:** Требует стабильного интернета.

## ⚙️ Математическое ядро (Метод SCS+C)
Независимо от того, каким путем снимок попал в программу (Путь 1 или 2), с ним происходят следующие шаги:

1.  **Приведение сеток:** Каналы Sentinel-2 имеют разное разрешение. B12 (20 м) и SCL (20 м) «натягиваются» на сетку B04 (10 м).
2.  **Морфометрия:** По цифровой модели рельефа (DEM) вычисляется уклон (Slope) и экспозиция (Aspect) для каждого пикселя.
3.  **Расчет `cos(i)`:** Вычисляется угол падения солнечных лучей на склон.
4.  **Маска леса:** Чтобы не калибровать воду или виноградники, мы оставляем только пиксели с высоким NDVI (> 0.65) и уклоном (> 5°). *(Порог 0.65 научно обоснован для региона Рейнланд-Пфальц).*
5.  **Калибровка `C`:** Через линейную регрессию между яркостью леса и `cos(i)` вычисляется коэффициент рассеянного света `C`. *(В коде применяется поправка `BOA_ADD_OFFSET = -1000` для сцен после 2022 года).*
6.  **Коррекция:** Яркость склонов выравнивается по формуле SCS+C.
7.  **Контроль качества:** Вычисляется корреляция Пирсона (`r`). Если `|r| < 0.1`, значит, рельеф больше не влияет на яркость, и сцена прошла проверку.

## 🚀 Как запустить?

### Подготовка (единая для обоих путей)
1. Установите окружение (рекомендуется через `mamba` или `conda`):
```bash
mamba create -n forest_env -c conda-forge python=3.11 "numpy<1.24" rasterio rioxarray xarray scipy pandas pyyaml shapely pystac-client planetary-computer dask
mamba activate forest_env
```
2. Убедитесь, что в файле `config.yaml` верно указан путь к DEM (`dgm10_trier.tif`) и координаты вашего AOI.

### Запуск ПУТИ 1 (Локально)
1. Скачайте снимки и положите в `data/raw/` (файлы `*_B04.tif`, `*_B08.tif`, `*_B12.tif`, `*_SCL.tif` и `*_MTD_TL.xml`).
2. Запустите:
```bash
python run_m1_local.py
```

### Запуск ПУТИ 2 (Облако/STAC)
1. Запустите скрипт (он сам найдет сцены за 2019-2020 годы):
```bash
python fetch_data_stac.py
```
2. Дождитесь окончания. Скрипт создаст файл `m1_stac_audit.csv` с отчетом.

## 📊 Результаты (Выходные данные)
После работы любого из двух путей, в папке `data/output/` появятся файлы:
*   `{scene_id}_B04_corr.tif`
*   `{scene_id}_B08_corr.tif`
*   `{scene_id}_B12_corr.tif`

Это **скорректированные каналы**, готовые к передаче в Модуль 2 (расчет NBR). 
Также будет создан файл `audit.csv`, в котором записаны коэффициенты `C` и показатели точности коррекции (`r`).

## ⚠️ Важные нюансы
*   **Смещение ESA:** Для сцен после января 2022 года ESA добавляет сдвиг +1000. Скрипт автоматически считывает метаданные и вычитает этот сдвиг перед калибровкой.
*   **Почему B12 иногда падает?** Канал SWIR (B12) очень чувствителен к наличию виноградников и сухой травы. Если в маску леса попадает много таких пикселей, свободный член регрессии завышается, и коэффициент `C` вылетает за допустимые пределы (0–5). В этом случае сцена отбраковывается (флаг `scsc_processed=0`), чтобы не портить временной ряд.
